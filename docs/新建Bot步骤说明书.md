# 新建 Agent 步骤说明书

<p align="right"><a href="新建Bot步骤说明书.md">中文</a> | <a href="新建Bot步骤说明书.en.md">English</a></p>

照着做就能建出一个能用的企微 Agent。**全程不需要改 Python 代码。**

主线用可视化配置页面（点点选选就行）。每个步骤下面都有折叠的
「不想用页面？」，里面是等价的命令行做法。

- 预计耗时：40 分钟（大部分时间花在写提示词上）
- 需要你会：填表单、复制粘贴
- 不需要你会：Python、YAML、MCP 协议

字段的详细含义查 [配置参考](配置参考.md)。

## 步骤 0：装环境

需要 Python 3.11 或更高。

```bash
python --version
```

预期：`Python 3.11.x` 或更高。低于 3.11 请先升级（框架用到了
`BaseExceptionGroup`，3.10 及以下会报语法错误）。

进入项目目录装依赖：

```bash
cd bot-demo
pip install -r requirements.txt
```

> **Windows 上可以跳过这一步** —— 双击 `start.bat`，
> 它会自己检查 Python 和依赖，缺什么装什么。

<details>
<summary>装不上怎么办</summary>

- `python` 不是命令 —— Python 没装或者装的时候没勾「Add Python to PATH」。
  重装一次，注意勾上那个选项。
- 公司网络装不上包 —— 找同事要内网 pip 源：
  `pip install -i <内网源地址> -r requirements.txt`
</details>

## 步骤 1：拿企微凭证

去企微管理后台：**智能机器人 → 新建机器人 → 进入机器人 → API模式 → 长连接**。

记下两个值：

- **bot_id**
- **secret**

> **让超管来建Agent。** 由超管创建的Agent，收到消息时能拿到明文工号
> （`L220104` 这种）；否则拿到的是加密串，业务系统认不了，
> 后面要多写一段映射代码。步骤 4 会当场验证这一点。

同时确认另外两组信息：

- **MCP 服务端地址** —— 问中台负责人要
- **LLM 端点和 key** —— 问 AI 平台负责人要

## 步骤 2：打开配置页面

**Windows**：双击项目目录里的 `start.bat`。

**macOS / Linux**：

```bash
./start-ui.sh
```

浏览器会自动打开 `http://127.0.0.1:8771/`。命令行窗口不要关，
关掉页面就停了。

> 这个页面只有你这台电脑能访问，不会暴露到网络上 ——
> 它能读写真实密钥，所以是故意这么设计的。

<details>
<summary>不想用页面？</summary>

```bash
python -m botkit ui --no-browser    # 只起服务不开浏览器
python -m botkit ui --port 8888      # 换端口
python -m botkit --help              # 看全部命令
```

后面所有步骤都能纯命令行 + 编辑器完成，各步骤的折叠块里有对应做法。
</details>

<details>
<summary>页面打不开怎么办</summary>

- **端口被占用**（默认 8771）—— 命令行会提示，换一个：`python -m botkit ui --port 8888`
- **浏览器没自动打开** —— 手动访问命令行里打印的那个地址
- **页面白屏** —— 按 F12 打开控制台看报错，把报错发给维护这个框架的人
</details>

## 步骤 3：新建Agent并填密钥

1. 点左上角 **「新建」**，输入名字（比如 `hr-assistant`）。
   字母开头，只能用字母、数字、下划线、连字符。
2. 创建后自动跳到 **「密钥」** 页。这一页列出的条目是根据配置自动算出来的，
   把步骤 1 拿到的值填进去。

填完点右下角 **「保存」**（或按 `Ctrl+S`）。

**`LLM_API_URL` 最容易填错**：默认用官方 SDK，地址要**填到 `/v1` 为止，
不要带 `/chat/completions`**，SDK 会自己拼。填错了保存时会当场告诉你怎么改。

左侧Agent名字前面的圆点会从**红变绿** —— 绿色表示配置能通过校验了。

<details>
<summary>不想用页面？</summary>

```bash
python -m botkit new hr-assistant
copy bots\hr-assistant\.env.example bots\hr-assistant\.env    REM Windows
cp bots/hr-assistant/.env.example bots/hr-assistant/.env      # macOS/Linux
```

然后编辑 `bots/hr-assistant/.env` 填 6 个值，再 `python -m botkit validate bots/hr-assistant`。
</details>

## 步骤 4：确认能认出用户是谁

**这一步最容易卡，趁早做掉。**

Agent要知道"现在是谁在说话"，才能代表这个人去建工单、提申请。
企微给的用户 ID 有可能是明文工号，也有可能是加密串。

在「密钥」页往下滚，有个 **「验证企微连接」** 区：

1. 先点 **「测试凭证」** —— 应该显示"企微凭证正确"。
2. 再点 **「等我在企微 @ 一句话」**，然后切到企业微信，
   **@ 你的Agent** 发一句话（比如"测试"）。

页面会显示：

| 项 | 你想看到的 |
|---|---|
| 识别到的用户 ID | `L220104` 这种明文工号 |
| 看起来像加密串吗 | 不像，是明文 |
| 身份校验结果 | 通过（绿色） |

看到绿色的"身份校验通过"就可以进下一步。

<details>
<summary>「测试凭证」失败：853000 invalid bot_id or secret</summary>

`.env` 里的 bot_id 或 secret 不对。回步骤 1 重新复制，注意别把前后空格带进来。
</details>

<details>
<summary>点了「等我 @ 一句话」但一直没反应</summary>

- 确认Agent已经被拉进那个群，或者你在跟它单聊
- 群里必须 **@ 它**，直接发消息它收不到
- 确认企微后台里Agent是「API模式 / 长连接」，不是「回调模式」
</details>

<details>
<summary>身份校验不通过，但 ID 看起来是明文工号</summary>

格式校验写严了。去 **「身份与安全」** 页，把「工号格式校验」改成合适的选项，
或者先选「不校验」。改完保存，再回来测一次。
</details>

<details>
<summary>身份校验不通过，ID 是 wo1234xxxx== 这种加密串</summary>

业务系统认不了这个 ID，有两条路：

1. **推荐**：让超管重建Agent，通常就能拿到明文工号。回步骤 1。
2. 自己做映射：编辑 `bots/<你的bot>/hooks.py`，取消注释
   `resolve_identity` 那段，写一个"加密 ID → 工号"的查表逻辑；
   再把「身份与安全」页的身份来源改成「自定义（hooks.py）」。
   这需要你有一份映射关系（一般要通过企微自建应用换取）。
</details>

<details>
<summary>不想用页面？</summary>

```bash
python tools/wecom_probe.py bots/hr-assistant
```

然后去企微 @ Agent发一句话，看控制台输出。`Ctrl+C` 退出。
</details>

## 步骤 5：勾选工具

Agent的能力来自 MCP 服务端提供的工具。

切到 **「工具」** 页，顶部是 **「MCP 服务端」** 管理区。默认有一个服务端。
**如果这个Agent要连多个中台**（比如同时接 IT 工单和 CRM），点
**「＋ 添加一个服务端」** 再加：每个填标识名（自取，如 `oa`、`crm`，必须唯一）、
地址（在每个服务端的 **「地址」** 框里直接填明文 URL，比如
`https://mcp.example.com/oa`；保存时会自动存进本地 `.env`，不会进 git，
也不会显示在「密钥」页）、身份透传头。多个服务端的工具会合并给模型。

配好服务端后点 **「探测全部服务端的工具」**（或某个服务端旁的
**「只探测这个」**）。页面会连上，把每个服务端实际提供的工具列成勾选框，
每个都带描述和参数。

**勾上这个Agent真正需要的，其他不勾。**

> 别偷懒全勾或者留空。工具一多模型就容易选错，每次请求还白带一堆
> 参数说明浪费 token。一个典型的例子：中台提供 26 个工具，
> 而一个专做工单的Agent只需要其中 2 个。

勾完保存。

<details>
<summary>探测报「配置还没通过校验」</summary>

先回步骤 3 把密钥填全并保存，左侧圆点变绿了再来探测。
</details>

<details>
<summary>探测报连不上（getaddrinfo failed / connection attempts failed）</summary>

- `getaddrinfo failed` —— 域名解析不了。检查 MCP 地址有没有拼错，
  以及你的机器能不能访问那个地址（可能要连内网/VPN）。
- `All connection attempts failed` —— 地址能解析但连不上。
  确认端口对不对、服务端在不在跑。
</details>

<details>
<summary>工具列出来了，但调用时返回「该操作需要先登录认证」</summary>

服务端要求浏览器登录，但群聊里没有浏览器环境。需要服务端针对
Agent来源开启免认证策略 —— 它会识别请求头 `X-MCP-Identity`
或参数里的工号来放行。

**这不是你能在Agent侧解决的。** 找中台负责人，跟他说：
你已经在每次请求带上了 `X-MCP-Identity: <工号>`，需要他为这个来源
放行指定的几个工具。配好之后Agent侧不用改任何东西。
</details>

<details>
<summary>不想用页面？</summary>

```bash
python tools/mcp_probe.py bots/hr-assistant                       # 列出全部工具
python tools/mcp_probe.py bots/hr-assistant --call get_xxx        # 试调一个
```

然后手动把工具名填进 `bot.yaml` 的 `mcp.servers[].allow_tools`。
</details>

## 步骤 6：绑定身份（安全关键）

切到 **「身份与安全」** 页，看下半部分那个黄色的
**「防止模型替别人操作」** 区。

**为什么必须配**：模型会自己编参数。如果某个工具有"这是谁提的"这类参数
（工单的提交人、报销的申请人、请假的员工号），用户随口一句
"帮张三报个故障"，模型就可能把提交人填成张三。

点 **「添加一条绑定」**，从下拉里选：

```
[create_it_ticket] 的参数 [work_code] = 当前用户
```

两个下拉里的选项都来自步骤 5 探测到的真实工具和参数，
所以不会填错名字。页面还会自动猜哪个参数是"操作人"，一般不用改。

**凡是"代表某人操作"的工具都加一条。** 配完保存。

这是代码层面的保证：框架会在真正发起调用前，用企微那边拿到的可信身份
覆盖掉模型填的值。比在提示词里写"不许编造工号"可靠得多 ——
提示词是能被绕过的。

## 步骤 7：写提示词

切到 **「提示词」** 页。

**这一步决定Agent好不好用，比调任何参数都重要。** 值得多花点时间。

按四段写：

```markdown
# 角色
你是 HR 助手，运行在企业微信里，帮同事处理请假、报销、考勤查询。

# 核心任务
同事会用自然语言说他要办什么，你判断该调哪个工具，
把信息补全后提交，然后把结果告诉他。

# 工作流程
1. 先调用 get_leave_types 拿到假期类型列表。
2. 根据同事的描述，从返回结果里匹配出 leave_type_id。
3. 确认开始时间、结束时间、事由都有了，再调用 submit_leave。
   - 员工号已由系统提供，不需要问。
   - 严禁自己编造 leave_type_id，必须来自第 1 步的返回。

# 回答要求
1. 用中文简洁回答。
2. 信息不全时主动追问，不要猜。
3. 提交成功后把单号和状态清晰告知。
4. 与本职无关的闲聊，简短回应后引导回正题。
5. 不要把内部 ID 展示给用户。
```

几条实践经验：

- **工具怎么用不用你写**，模型能看到每个工具自己的描述和参数。
  这里重点写**按什么顺序调**和**不许做什么**。
- **约束用硬词**。"严禁"、"必须"比"建议"、"尽量"有效得多。
- **模型老漏某一步，就把那一步单独拎出来写成一条编号规则**，
  别混在段落里。
- **身份参数写一句"已由系统提供"**。虽然步骤 6 已经从代码层面
  保证了，但告诉模型能省它多问一句。

## 步骤 8：核对配置摘要

切到 **「其他」** 页，看底部的 **「当前配置摘要」**（密钥已打码）。

**逐项核对**，尤其这几处：

- `api_url` 是不是到 `/v1` 为止
- **白名单**里是不是你要的那几个工具
- **强制注入**那行在不在 —— 空的话回步骤 6
- **校验正则**能不能匹配上步骤 4 看到的真实工号

顺便看一下「代码扩展点」那块，正常应该显示
"所有扩展点都是注释状态，当前不生效"。

<summary>不想用页面？</summary>

```bash
python -m botkit validate bots/hr-assistant
```
</details>

## 步骤 9：在线预览测试

**不连企业微信，先在页面里跟Agent聊两句看效果。** 这一步能在正式上线前
把提示词、工具、身份注入一起验证掉，比连上企微再试快得多。

切到 **「预览测试」** 页，在输入框里发一句真实用户会说的话
（比如“我想请三天年假”），回车发送。

页面会显示：
- Agent调用了哪些工具（点开能看到实际参数和返回）
- 最终回复

对着结果检查三件事：

1. **工具选对了吗** —— 该调的调了、不该调的没调
2. **身份注入生效了吗** —— 展开工具调用，看“提交人/申请人”这类参数
   是不是你在「用哪个身份测试」里填的那个，而不是模型编的
3. **回复质量** —— 答得对不对、有没有漏问关键信息

不满意就回步骤 7 改提示词，保存后再来发一句，即时见效。

> **预览会真的执行工具。** 它走的是和正式运行一模一样的流程，
> 所以如果提示词触发了“创建工单”这类动作，这里会**真建一张单**。
> 拿测试数据试，别用真实业务信息。

<details>
<summary>预览报错怎么办</summary>

预览要真的连上 LLM 和 MCP，所以：

- **“配置还没通过校验”** —— 回步骤 3/8 把配置弄对。
- **“调用大模型失败”** —— LLM 的地址或 key 不对，回步骤 3 检查。
- **“调用 MCP 工具失败”** —— 工具服务端连不上或要求登录，回步骤 5。
- **“身份不符合 identity.pattern”** —— 在「用哪个身份测试」里填一个
  符合格式的工号，或回步骤 6 调校验规则。

这些都不是 bug，预览就是要真连才有意义。
</details>

<details>
<summary>不想用页面？</summary>

没有等价的命令行预览。要么用页面，要么直接走步骤 10 连企微实测。
</details>

## 步骤 10：启动并在群里验证

配置页面只管配置，**启动Agent要用命令行**（它是长期跑的服务，
交给你们现有的运维方式管更合适）。

新开一个命令行窗口：

```bash
cd bot-demo
python -m botkit run bots/hr-assistant
```

预期输出：

```
2026-09-17 13:19:41 [hr-assistant] INFO  [botkit.runtime] 正在启动Agent hr-assistant
2026-09-17 13:19:42 [hr-assistant] INFO  [botkit.runtime] LLM 后端    : openai（... / qwen3.7-plus）
2026-09-17 13:19:42 [hr-assistant] INFO  [botkit.runtime] MCP 服务端  : main ... 工具=get_leave_types、submit_leave
2026-09-17 13:19:42 [hr-assistant] INFO  [botkit.runtime] WebSocket 已连接
2026-09-17 13:19:43 [hr-assistant] INFO  [botkit.runtime] 认证成功，Agent hr-assistant 已上线
```

看到 **`已上线`** 就通了。保持窗口开着，去企微群里 @ 它。

### 至少验证这 5 条

| 输入 | 预期 |
|---|---|
| `@Agent 我想请三天年假` | 走完流程，返回单号 |
| `@Agent`（只 @ 不说话） | 回你配的「只 @ 没说话」文案 |
| `@Agent 重新开始` | 回「已重置」文案，上下文清空 |
| 连续两句有关联的话 | 第二句能接上第一句的上下文 |
| `@Agent 帮张三请假` | **单子的申请人还是你自己** |

最后那条最重要 —— 它验证步骤 6 的绑定真的生效了。跑完看日志里有没有这行：

```
WARNING [botkit.engine] LLM 给工具 submit_leave 的 employee_code 传了 'xxx'，已用可信身份 'L220104' 覆盖
```

有这行说明防伪造生效了。

<details>
<summary>回复「抱歉，处理过程中发生异常」</summary>

看运行窗口的日志，往上找 ERROR 那几行，真正的原因在那里。
在配置页面「其他」页把日志级别改成 `DEBUG` 能看到更多细节。
</details>

<details>
<summary>回复「无法识别你的工号」</summary>

回步骤 4 处理。
</details>

<details>
<summary>回复「处理超时（工具调用轮次过多）」</summary>

模型在反复调工具打转。看日志里它在循环调哪个，然后回步骤 7，
把那一步的约束写成单独一条编号规则。调大轮次上限治不了本。
</details>

<details>
<summary>答得不对、漏步骤、乱编 ID</summary>

提示词的问题，回步骤 7。把出问题的那条约束写得更硬更具体。
改完保存，重启Agent即生效。
</details>

## 步骤 11：上线检查清单

交给同事日常使用前，过一遍：

## 卡住了看这里

按症状查：

| 症状 | 去哪 |
|---|---|
| `python` 不是命令 / 缺依赖 | [步骤 0](#步骤-0装环境) |
| 配置页面打不开 / 端口占用 | [步骤 2](#步骤-2打开配置页面) |
| `853000 invalid bot_id or secret` | [步骤 4](#步骤-4确认能认出用户是谁) |
| @ 了Agent没反应 | [步骤 4](#步骤-4确认能认出用户是谁) |
| 回「无法识别你的工号」 | [步骤 4](#步骤-4确认能认出用户是谁) |
| MCP 连不上 / 要求登录 | [步骤 5](#步骤-5勾选工具) |
| 工具列表是空的 | [步骤 5](#步骤-5勾选工具) |
| 保存时报配置错误 | [步骤 3](#步骤-3新建Agent并填密钥) |
| 预览测试报错 | [步骤 9](#步骤-9在线预览测试) |
| 回「处理过程中发生异常」 | [步骤 10](#步骤-10启动并在群里验证) |
| 回答质量不行 | [步骤 7](#步骤-7写提示词) 或 [步骤 9](#步骤-9在线预览测试) |
| 想改某个具体行为 | [配置参考](配置参考.md) |

两个排查工具随时可以单独跑，不影响正在运行的Agent：

```bash
python tools/wecom_probe.py bots/你的bot    # 看企微给了什么身份
python tools/mcp_probe.py  bots/你的bot     # 看能拿到哪些工具
```

想看Agent内部到底怎么走的，把日志级别改成 `DEBUG`。

## 之后想改东西

大部分改动直接在配置页面点点就行，改完保存、重启Agent生效。

| 想改什么 | 页面上去哪 | 对应文件字段 |
|---|---|---|
| 角色、话术、流程约束 | 提示词 | `prompt.md` |
| 加/减能用的工具 | 工具 | `mcp.servers[].allow_tools` |
| 换模型、调超时 | 大模型 | `llm` |
| 欢迎语、报错提示、进度文案 | 文案 | `messages` |
| 上下文记几轮、多久过期 | 会话 | `session` |
| 群里按人隔离还是整群共享 | 会话 | `session.scope` |
| 工号格式、身份绑定 | 身份与安全 | `identity` |
| 日志详细程度 | 其他 | `logging.level` |
| 加帮助菜单这类固定回复 | （要写代码） | `hooks.py` 的 `on_message` |
| 给Agent加业务说明/术语/FAQ | 技能 | `skills`（文档放 `bots/_skills/`，勾选引用） |
| 开成 HTTP 接口给 Dify/门户用 | 对外接口 | `api`（详见[配置参考](配置参考.md#api-对外接口)） |
| 搬到别的环境/复制配置 | 标题栏「导出 JSON」/侧栏「导入」 | 导出不含密钥，导入后补密钥 |
| 改完想验证效果 | 预览测试 | — |
| 删掉一个Agent | 标题栏「删除这个Agent」 | 挪到 `bots/.trash/`，可找回 |

**页面和手改可以混着用。** 页面存盘时会保留 `bot.yaml` 里的注释，
所以你也可以直接用编辑器改文件，下次用页面打开还是好的。
