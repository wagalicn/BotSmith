    密钥

    这些值来自企微后台和平台管理员，存在本 bot 目录的 .env 里， 不会进 git。下面的条目是根据配置里用到的占位符自动列出来的。 如果这个Agent只做对外接口（不连企业微信），企微 bot_id / bot_secret 可以留空—— 去「对外接口」页开启 chat 接口即可。

    验证企微连接

    先确认凭证对不对，再确认Agent能不能认出说话的人是谁 —— 这两步是新建 bot 最容易卡住的地方。

    大模型

    工具

    Agent的能力来自 MCP 服务端提供的工具。可以接多个服务端 —— 比如同时连 IT 工单中台和 CRM。每个服务端配好后点「探测」， 把它实际有的工具列出来，勾上这个Agent需要用的。 勾得越少模型越不容易选错，也越省 token。

    MCP 服务端

    地址直接填明文，会存进本地 .env、不进 git
    需要先保存并通过校验

    身份与安全

    防止模型替别人操作

    模型会自己编参数。如果某个工具有「这是谁提的」这类参数 （工单的提交人、报销的申请人），一定要在这里绑定成「当前用户」。 绑定之后，框架会在真正调用前用企微那边拿到的身份覆盖掉模型填的值。

    提示词

    写清这个Agent是谁、要做什么、按什么顺序调工具、不许做什么。 这一步决定Agent好不好用，比调任何参数都重要。 约束用「严禁」「必须」这类硬词比「建议」有效。 文件后缀是 .md，但不强制 Markdown 语法 —— 整段文本会原样交给模型，右边的预览只是帮你看排版。

    技能

    技能是补充给Agent的说明文档（业务规则、术语表、FAQ 等）。 启用后，勾选的文档会拼进系统提示词，Agent遇到需要理解的说明就能参考。 文档存在共享目录里，多个Agent可以各自勾选需要的那几份。

    会话上下文

    文案

    Agent在各种情况下说的话。留空则用框架默认值。

    重置关键词

    用户发这些词会清空对话。整条消息完全等于其中一个才算命中。

    工具进度提示

    调用工具前推给用户的提示。工具慢的时候体验差别很大。

    前置拦截

    用户消息命中规则时，直接回固定文案，不进大模型 —— 快、省 token、答案稳定。 适合帮助菜单、常见问答、固定话术。命中优先级：重置关键词 > 拦截规则 > 大模型。

    对外接口

    把这个Agent开成一个 HTTP 接口（POST /chat），供 Dify、内部门户或其它系统调用。 可以和企业微信同时用，也可以只开接口、不连企微。 调用方负责传 user（用户标识）和 session_id（会话 ID）。

    预览测试

    不连企业微信，直接在这儿跟Agent聊两句看效果。走的是和正式运行 一模一样的流程 —— 真调大模型、真调 MCP 工具。用来验证提示词写得对不对、 工具选得全不全、身份注入生效没有。

    注意：预览会真的执行工具。如果提示词触发了「创建工单」 这类动作，这里会真建一张单。拿测试数据试，别用真实业务信息。

    按 Enter 发送，Shift+Enter 换行。预览的对话不会保存。
